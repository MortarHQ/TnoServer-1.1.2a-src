# 阅读指南：怎么用这套「源码 wiki」回答整合包问题

> 这套东西是**反编译出来的真实源码**（`codewiki/sources/`）＋由源码机械生成的**结构 wiki**（`codewiki/wiki/`）＋**配置逐项文档**（`codewiki/configs/`）。
> 目标：任何"这个整合包里 X 是怎么实现的 / 这个配置项有什么用"的问题，都能落到**具体文件与行**。

## 一、先确定要查哪个 mod

1. 问的是物品/方块/生物/维度 → 查 `dsh/kb/80-全物品/` 或 `dsh/kb/30-世界/`，拿到 `命名空间:路径`；
   命名空间就是 modid（少数情况是共享命名空间）。
2. 问的是技能/遗物/任务/配置 → 对应 `dsh/kb/20-玩法系统/`、`50-进度/`、`60-服务器/`。
3. 拿到 modid 后 → `codewiki/wiki/<modid>/README.md`（包结构 + 关键类 + 事件 + Mixin + 配置类）。

## 二、定位到类

在 `codewiki/index/classes.tsv`（5 万+ 类）里搜类名或包名：

```bash
# 按类名关键字（例：找所有和 magicule 有关的类）
awk -F'\t' 'tolower($3) ~ /magicule/' /storage/mc/codewiki/index/classes.tsv

# 只看某个 mod 的事件处理类
awk -F'\t' '$1=="tensura" && $9>0' /storage/mc/codewiki/index/classes.tsv

# 找 Mixin 类
awk -F'\t' '$10==1' /storage/mc/codewiki/index/classes.tsv | head

# 找实现了某父类的类
awk -F'\t' 'tolower($5) ~ /relicitem/' /storage/mc/codewiki/index/classes.tsv | head
```

## 三、读源码

源码目录就是 modid：

```bash
ls /storage/mc/codewiki/sources/tensura/
grep -rn "magiculeSpawn" /storage/mc/codewiki/sources/tensura/ --include=*.java | head
grep -rn "@SubscribeEvent" /storage/mc/codewiki/sources/tensura/ --include=*.java -l
```

**注意**：反编译保留了原始类名/方法名/字符串常量，但**局部变量名**被抹成 `var1`、`lambda$xxx$1`；`switch` 可能被还原成 `switch(x) { case 0: ... }`。数值、调用关系、事件订阅、注册表内容都是可靠的。

## 四、查配置

```bash
# 某个配置项到底是谁在读
grep -rn "magicEngineRange" /storage/mc/codewiki/sources/ --include=*.java | head
# 看这个 mod 的全部配置项
cat /storage/mc/codewiki/configs/<modid>.md
```

`configs/<modid>.md` 里每一项都列了：配置文件、键、默认值、**本实例实际值**、读它的类（`类#方法`）。

## 五、常见问题的推荐路径

| 问题 | 路径 |
|---|---|
| "某物品怎么获得/能不能合成" | `dsh/kb/80-全物品/`（获取标记）→ 配方 JSON 在 `TnoServer-1.1.2a/data/<mod>/recipe/` |
| "某技能/遗物的具体数值" | 先看 `dsh/kb/20-玩法系统/` → 再 `grep 技能id sources/<mod>/` 找到类 → 读 `config/` 对应段 |
| "这个事件触发时会发生什么" | `awk -F'\t' '$9>0' classes.tsv` 找事件类 → 读 `@SubscribeEvent` 方法体 |
| "某 Mixin 改了什么原版行为" | `awk -F'\t' '$10==1'` 找 Mixin → 读 `@Inject/@Redirect/@ModifyVariable` 注解与方法体 |
| "配置项改了有什么影响" | `configs/<mod>.md` → 点开读取者类看逻辑 |
| "这个 mod 和哪些 mod 交互" | `wiki/<mod>/README.md` 的"依赖" + `grep -rn "<其他modid>" sources/<mod>/` |

## 六、边界

- 反编译**不能恢复注释、Javadoc、原始局部变量名、泛型擦除前的部分签名**；也不要指望拿到作者的开发注释。
- 某些类会被 Vineflower 标 `// $VF: Couldn't be decompiled`，此时用 `dsh/tools/jvmdis.py` 直接看字节码。
- 混淆过的第三方库（少数 jar 内嵌）反编译后类名仍是 `a/b/c`，属正常。
